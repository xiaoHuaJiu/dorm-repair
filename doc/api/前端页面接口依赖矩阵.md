# 前端页面接口依赖矩阵

本文对应 `FRONTEND-PLAN.md` 的 F0-02。状态含义：

- **已具备**：现有接口文档明确记录已实现，可进入前端联调。
- **待联调**：接口契约已有说明，但仍需用实际后端响应核对。
- **缺失/阻塞**：现有接口文档没有可供页面完成业务闭环的正式接口。

前端不得为“缺失/阻塞”接口生成演示数据；页面应展示空状态、错误状态或禁用对应操作，并保留明确提示。

## 1. 公共协议

| 能力 | 接口/协议 | 状态 | 前端约定 |
|---|---|---|---|
| 登录 | `POST /api/auth/login` | 已具备 | 成功返回 `token` 和 `user`；JWT 使用 `Authorization: Bearer` |
| 学生注册 | `POST /api/auth/register` | 已具备 | 仅提交已确认的五个字段；注册成功不自动登录 |
| 当前用户 | 未记录 | 缺失/阻塞 | 页面刷新后的用户信息恢复无法仅依赖正式接口完成 |
| 文件上传 | 未记录 | 缺失/阻塞 | 报修和维修图片功能阻塞，不在前端生成假 URL |
| 分页 | `pageNum`、`pageSize` | 待联调 | 页码从 1 开始，`pageSize` 最大 100 |
| 统一响应 | `{ code, message, data }` | 已具备 | HTTP 状态与业务码同时判断 |

### 分页字段待确认

`前端联调接口说明.md` 与 `基础配置接口.md` 使用 `data.records`，`公共接口响应规范.md` 的示例使用 `data.list`。前端目标类型先按总联调文档采用 `records`，后端需统一契约后再开始列表联调。

## 7. 已确认的字段和枚举基线

- 工单列表字段以 `前端联调接口说明.md` 第 3 节为准，包括 ID、编号、状态、学生、故障类型、四级位置、负责人、期限和异常标记。
- 工单详情聚合对象为 `baseInfo`、`processRecords`、`materialRecords`、`reworkRecords`、`evaluation`、`flows`。
- 页面展示状态名称为：待派单、待接单、维修中、待确认、已中断、返工中、已完成、已取消。
- 状态对应的整数值尚未在总联调文档中完整列出，前端不得自行编造映射；在后端补充契约前，以响应的 `statusName` 展示，操作权限仍视为阻塞。
- 位置层级固定为单位/校区、区域、楼栋、房间，类型值依次为 1、2、3、4。

## 8. 后端并行开发阻塞清单

1. 统一分页集合字段为 `records` 或 `list`。
2. 补充角色枚举和完整工单状态数值映射。
3. 补充当前用户、文件上传、创建报修、重复检测和取消工单接口。
4. 补充学生全校工单和维修人员全校只读工单及详情访问契约。
5. 补充维修命令、评价返工、请假、消息、审批和人工派单接口。
6. 补充区域与故障类型的删除接口，或确认前端取消删除能力。
7. 确认 `flows` 覆盖工单整个生命周期和全部异常节点。

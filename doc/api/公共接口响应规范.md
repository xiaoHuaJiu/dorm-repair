# 公共接口响应规范

## 统一响应体

所有控制器和 Spring Security 错误响应均使用以下结构：

```json
{"code": 0, "message": "success", "data": {}}
```

`code=0` 表示成功；失败时 `data` 为 `null`。前端必须同时判断 HTTP 状态与 `code`，不得只依赖其中一个。

## HTTP 状态与通用错误码

| HTTP 状态 | 错误码 | 含义 |
|---|---:|---|
| 200 | 0 | 请求成功 |
| 400 | 10001 | 请求参数错误 |
| 401 | 10002 | 未登录或登录状态已失效 |
| 403 | 10003 | 无权限访问 |
| 404 | 10004 | 数据不存在 |
| 409 | 10005 | 数据状态已发生变化 |
| 405 | 10006 | 当前操作不允许 |
| 500 | 50000 | 系统异常，请稍后重试 |

认证补充错误码：`11001` 表示用户名或密码错误，`11002` 表示账号不可用。登录请求为 `POST /api/auth/login`：

```json
{"username":"admin","password":"本机环境变量中的密码"}
```

成功响应的 `data` 包含 `token` 和 `user`（`userId`、`username`、`realName`、`roleType`），不返回密码或密码哈希。

系统异常响应不得包含异常消息、SQL、连接地址、文件路径或堆栈。

## 分页协议

请求参数：`pageNum` 为从 1 开始的页码，默认 1；`pageSize` 默认 10，最大 100。

```json
{"pageNum": 1, "pageSize": 10}
```

分页数据放入统一响应体的 `data`：

```json
{"code":0,"message":"success","data":{"total":0,"pageNum":1,"pageSize":10,"list":[]}}
```

无数据是正常查询结果，返回 HTTP 200、`total=0` 和空数组，不按系统异常处理。

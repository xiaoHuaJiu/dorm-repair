# 基础配置接口

本文记录 PLAN-2 已实现的后端接口。所有响应均使用统一 `Result`；分页数据位于 `data.records`，同时包含 `total`、`pageNum` 和 `pageSize`。

## 学生注册

- `POST /api/auth/register`：匿名可访问。
- 请求字段：`username`、`password`、`confirmPassword`、`realName`、`phone`。
- 服务端固定创建学生角色，忽略客户端额外提交的角色字段；注册成功不自动签发令牌。

## 故障类型

- `GET /api/admin/fault-types`：管理员分页查询。
- `POST /api/admin/fault-types`：管理员新增。
- `GET /api/admin/fault-types/{id}`：管理员查看详情。
- `PUT /api/admin/fault-types/{id}`：管理员修改名称、排序和备注，编码创建后不修改。
- `PUT /api/admin/fault-types/{id}/status?status=0|1`：管理员启停。
- `GET /api/fault-types/enabled`：任意已登录用户查询启用项。

分页条件包括 `pageNum`、`pageSize`、`typeCode`、`typeName` 和 `status`。

故障类型字段：`id`、`typeCode`（最长 50，创建后不变）、`typeName`（最长 100）、`status`（1 启用/0 停用）、`sortNo`、`remark`（最长 500）。

> F4 状态：后端无删除接口。前端删除按钮禁用并以 title 提示“后端暂无删除接口，暂不支持删除”，待后端补充后开放。

## 位置树

位置树现为四级结构：`1 单位/校区 → 2 区域 → 3 楼栋 → 4 房间`。房间节点的 `parentId` 必须指向楼栋。

- `GET /api/admin/areas/tree`：管理员查询包含停用节点的完整树。
- `POST /api/admin/areas`：管理员新增节点。
- `GET /api/admin/areas/{id}`：管理员查询详情。
- `PUT /api/admin/areas/{id}`：管理员修改名称、排序和备注，不允许修改父节点。
- `PUT /api/admin/areas/{id}/status?status=0|1`：管理员启停。
- `GET /api/areas/tree`：任意已登录用户查询有效树。
- `GET /api/areas/{parentId}/children`：任意已登录用户查询有效直接子节点；根节点使用 `parentId=0`。

新增请求字段：`parentId`（必填，根节点传 `0`）、`areaCode`（必填，最长 50）、`areaName`（必填，最长 100）、`areaType`（必填，由父节点类型自动确定）、`sortNo`、`remark`（最长 500）。树节点响应包含 `id`、`parentId`、`areaCode`、`areaName`、`areaType`、`status`、`sortNo`、`children`。

> F4 状态：后端无删除接口。前端删除按钮按“无子节点则禁用并 title 提示、有子节点则点击提示‘请先删除下级节点’（F4-01 要求）”处理；后端补充删除接口后，无子节点节点开放确认删除。

## 维修人员

- `GET /api/admin/workers`：管理员分页及条件查询。
- `POST /api/admin/workers`：管理员创建维修人员。
- `GET /api/admin/workers/{id}`：管理员查看组合详情。
- `PUT /api/admin/workers/{id}`：管理员修改维修人员编号和备注。
- `PUT /api/admin/workers/{id}/work-status?status=0|1|2`：更新维修业务状态。
- `PUT /api/admin/workers/{id}/account-status?status=0|1`：更新登录账号状态。

创建时传 `existingUserId` 表示绑定已有的正常维修人员角色账号；不传时必须提供 `username`、`password`、`realName`，由服务端在同一事务中创建账号和维修人员记录。

创建字段（新建账号模式）：`username`（最长 100）、`password`（8—64 字符）、`realName`（最长 100）、`phone`（空或 `1[3-9]\d{9}`）、`workerNo`（必填，最长 50）、`remark`（最长 500）。更新字段：`workerNo`、`remark`。

账号状态 `userStatus`：1 启用/0 停用；维修业务状态 `workStatus`：0 正常/1 请假中/2 停用。前端“停用账号”使用账号状态接口，弹窗确认后调用。

> F4 状态：维修人员卡片中的“当前剩余 N 张工单”负载字段依赖 F5 工单查询，本阶段固定显示“—”，待 F5 补充后对接。

## 技能和负责区域

- `GET /api/admin/workers/{id}/fault-types`：查询全部技能关系及状态。
- `PUT /api/admin/workers/{id}/fault-types`：批量保存，正文为 `{ "faultTypeIds": [1, 2] }`。
- `GET /api/admin/workers/{id}/area-scopes`：查询全部负责范围及状态。
- `PUT /api/admin/workers/{id}/area-scopes`：批量保存，正文中的 `scopes` 包含 `campusId`、可空的 `areaId` 和可空的 `buildingId`。

批量保存采用差集更新：已有关系启停复用，不物理删除；区域范围会校验真实父子关系，并用上级范围覆盖、停用冗余下级范围。

`faultTypeIds` 为 `@NotNull` 列表，允许提交空数组表示清空全部技能；每条负责范围必须选校区，`areaId`、`buildingId` 可为空。

## 工作时间方案

- `GET /api/admin/work-schedules`：管理员分页查询，可传 `scheduleName`、`status` 和 `date`。
- `POST /api/admin/work-schedules`：管理员新增。
- `GET /api/admin/work-schedules/{id}`：管理员查看详情。
- `PUT /api/admin/work-schedules/{id}`：管理员修改。
- `PUT /api/admin/work-schedules/{id}/status?status=0|1`：管理员启停。

启用方案的日期区间不得相交；开始日期不能晚于结束日期，上班时间必须早于下班时间。`createBy` 只取自当前登录用户。

新增字段：`scheduleName`（最长 100）、`startDate`/`endDate`（日期）、`workStartTime`/`workEndTime`（`HH:mm`）、`status`（1 启用/0 停用）、`remark`（最长 500）。前端提交时携带 `status=1`，结束日期早于开始日期或下班时间不晚于上班时间时前端拦截并提示。

## 权限与状态码

- 匿名访问受保护接口：HTTP 401。
- 学生或维修人员调用管理员接口：HTTP 403。
- 参数错误：HTTP 400。
- 数据不存在：HTTP 404。
- 唯一约束或日期区间冲突：HTTP 409。

具体数字业务码以 `ResultCodeEnum` 和《公共接口响应规范》为准。

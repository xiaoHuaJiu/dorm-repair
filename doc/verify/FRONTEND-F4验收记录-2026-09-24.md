# FRONTEND F4 验收记录(2026-09-24)

## 验收范围

- F4-01:四级区域树——单位/校区 → 区域 → 楼栋 → 房间,默认折叠,浏览态隐藏增删入口,编辑态按层级提供 `+`/`−`,底部新增根节点。
- F4-02:故障类型管理——卡片网格列表、新增、编辑、启用/停用。
- F4-03:工作时间配置——方案卡片列表、当前启用标记、新增弹窗、启停、时间范围校验。
- F4-04:维修人员管理——人员卡片列表、新建账号/绑定已有账号、编辑资料、账号启停、技能与负责区域配置。
- 四个页面均对照 `prototype/` 中 `admin-regions`、`admin-fault-types`、`admin-schedules`、`admin-workers` 原型逐项还原,不添加模拟数据。

## 交付物

- 页面:`views/admin/config/AreaManagementView.vue`、`FaultTypeView.vue`、`WorkScheduleView.vue`、`WorkerManagementView.vue`。
- 组件:`components/admin/RegionTreeNode.vue`(四级树递归节点)、`components/admin/WorkerCard.vue`(人员卡片)、`components/common/PaginationBar.vue`(分页条)。
- API 模块:`api/area.ts`、`api/faultType.ts`、`api/workSchedule.ts`、`api/worker.ts`、`api/successNotifier.ts`,全部直连后端真实接口,无演示数据。
- 常量与类型:`constants/config.ts`(区域类型 1—4 与层级映射、通用启停、维修工作状态 0/1/2)、`types/config.ts`(树节点、故障类型、工作时间、维修人员 DTO)。
- 路由:`router/index.ts` 注册 `/admin/config/workers|areas|schedules|fault-types` 四条管理员路由,`AdminAppShell` 侧栏自动显示。
- 样式:`styles/main.css` 追加区域树、工人卡片、方案卡片、故障卡片网格等原型样式。
- 测试:7 个新增测试文件 + `AdminAppShell.spec.ts` 更新侧栏断言;`vite.config.ts` 增加 `testTimeout: 15000`(全量并行时路由跳转类测试偶发超过默认 5s)。

## 自动化验证

在 `frontend` 目录执行:

```text
npm run test:run
Test Files  26 passed (26)
Tests       150 passed (150)

npm run typecheck
exit code 0

npm run build
built in 10.96s
exit code 0
```

说明:全量并行运行时,涉及路由跳转等待的测试(布局壳退出登录、路由守卫等)偶发超过默认 5s 超时,已把 `testTimeout` 提到 15000ms;`--no-file-parallelism` 串行模式下 150/150 同样全绿。

新增测试覆盖(59 个 F4 相关用例):

- `RegionTreeNode`:分支/叶子渲染、默认折叠、hidden 属性切换编辑态、房间无 `+`、add/remove 事件、无子节点禁用删除、停用标签、递归渲染与空提示。
- `AreaManagementView`:树加载、浏览/编辑切换、添加下级弹窗标题与类型、名称校验、提交参数(parentId=0 根节点)、删除有子节点提示、空态、错误重试。
- `FaultTypeView`:列表渲染、分页参数、新增/编辑提交、编码只读、启停切换、删除禁用提示、空态、错误重试。
- `WorkScheduleView`:列表与启用标记、新增校验(结束早于开始、下班不晚于上班)、提交携带 status、启停、空态、错误重试。
- `WorkerManagementView`:列表与状态、密码长度校验、新建/绑定双模式提交参数、编辑提交、账号停用确认、技能与区域保存(含校区必选校验)、空态、错误重试。
- `WorkerCard`:字段渲染、技能/区域真实接口加载、失败回退“—”、负载占位、事件传递。
- `PaginationBar`:总数/页码渲染、上一页/下一页事件。
- `AdminAppShell`:侧栏分组断言更新为“工作台 + 基础维护 4 项”。

测试侧发现并规避的问题:jsdom 的 `getComputedStyle` 对同一元素先后调用会缓存 `display` 值(浏览态先取到 `none` 后,编辑态属性切换不失效),故“显示/隐藏”断言改用 `hidden` 属性断言,与原型 `hidden` 属性实现方式一致。

## 人工验证路径

1. 启动后端(8811)与前端(`npm run dev`),管理员登录后依次访问:
   - `/admin/config/areas`:核对四级树默认折叠、编辑按钮切换、各级 `+`/`−` 可见性、底部新增根节点弹窗、删除提示与禁用态,与 `prototype/admin-regions.html` 逐项对照。
   - `/admin/config/fault-types`:核对卡片网格布局、启停 tag 颜色、新增/编辑弹窗、删除禁用提示,与 `prototype/admin-fault-types.html` 对照。
   - `/admin/config/schedules`:核对方案卡片(启用绿色/停用琥珀)、新增弹窗与时间校验、启停交互,与 `prototype/admin-schedules.html` 对照。
   - `/admin/config/workers`:核对人员卡片(状态 tag、技能、区域、负载“—”)、新增弹窗双模式切换、编辑、账号停用确认、技能与区域弹窗三级联动,与 `prototype/admin-workers.html` 对照。

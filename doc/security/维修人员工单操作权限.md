# 维修人员工单操作权限

## 身份与数据边界

维修人员接口只接受 JWT 中的当前用户身份。后端通过 `sys_user.id → repair_worker.id` 获得当前维修人员，任何请求参数都不能指定或覆盖操作人。

每次详情和写操作都校验 `repair_order.current_assignee_id`。非当前负责人访问或操作返回 HTTP 403 / 17002；不存在或已删除的工单返回 HTTP 404 / 17001。

## 状态边界

| 操作 | 允许的原状态 | 目标状态 |
|---|---|---|
| 接单 | 待接单 | 维修中 |
| 添加过程 | 维修中、返工中 | 不变 |
| 登记材料 | 维修中、返工中 | 不变 |
| 中断 | 维修中 | 已中断 |
| 恢复 | 已中断 | 维修中 |
| 提交结果 | 维修中、返工中 | 待确认 |

状态变更采用包含工单 ID、负责人和原状态的条件更新，并在事务内写入业务记录、流转和操作日志。状态过期或并发冲突返回 HTTP 409 / 10005，不覆盖数据库中的最新状态。

## 敏感信息边界

学生详情不返回材料使用明细。过程和结果图片字段仅保存已上传对象引用；PLAN-6 不提供文件上传能力。

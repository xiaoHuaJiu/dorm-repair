# 前端登录与路由权限

本文对应 `FRONTEND-PLAN.md` 的 F2 阶段，记录前端登录、注册、令牌与用户信息的处理方式，以及三端路由域的权限边界。后端鉴权实现见《登录用户上下文与安全响应.md》。

## 1. 登录与注册流程

- 登录调用 `POST /api/auth/login`，成功响应包含 `token` 和 `user`，前端保存后按 `user.roleType` 跳转对应端首页。
- 学生注册调用 `POST /api/auth/register`，前端只提交 `username`、`password`、`confirmPassword`、`realName`、`phone` 五个字段，不提交角色字段；服务端固定创建 `STUDENT` 账号。
- 注册成功不自动登录：前端清空密码字段并切回登录表单，不保留注册密码。
- 角色数值与后端 `UserRoleEnum` 一致：`1` 学生、`2` 维修人员、`3` 管理员。登录响应出现未知角色值时不进入任何业务端，并在表单内提示联系管理员。

## 2. 令牌与用户信息的本地存储

| 存储键 | 内容 | 用途 | 清理时机 |
|---|---|---|---|
| `dorm-repair-token` | JWT | 请求拦截器注入 `Authorization: Bearer` | 登出、接口 401 |
| `dorm-repair-user` | 登录响应中的 `user` 对象 | 页面刷新后恢复界面身份与路由守卫 | 登出、接口 401、缓存损坏 |

安全边界：

- 本地缓存仅用于界面展示和前端路由控制，不替代服务端鉴权；服务端每次认证重新检查账号状态，停用账号的旧令牌立即失效。
- 任何接口返回 HTTP 401 或业务码 10002 时，统一清理两个存储键并跳转登录页。
- 读取本地缓存时做结构与角色值校验，损坏数据直接丢弃，不抛出异常。
- 密码只存在于提交瞬间的内存变量，注册提交后立即清空，不写入任何持久化存储。

## 3. 角色路由域

| 路由域 | 允许角色 | 登录落点 |
|---|---|---|
| `/login` | 匿名 | 已登录访问自动跳回角色首页 |
| `/403`、`/404` | 匿名可访问 | 结果页 |
| `/student/*` | 学生（roleType=1） | `/student/home` |
| `/worker/*` | 维修人员（roleType=2） | `/worker/home` |
| `/admin/*` | 管理员（roleType=3） | `/admin/dashboard` |

## 4. 页面权限矩阵

| 页面 | 匿名 | 学生 | 维修人员 | 管理员 |
|---|---|---|---|---|
| `/login` 登录与注册 | ✓ | 跳回首页 | 跳回首页 | 跳回首页 |
| `/403` 无权限、`/404` 未匹配 | ✓ | ✓ | ✓ | ✓ |
| `/student/home` 学生首页 | 跳登录 | ✓ | 403 | 403 |
| `/worker/home` 维修工作台 | 跳登录 | 403 | ✓ | 403 |
| `/admin/dashboard` 管理工作台 | 跳登录 | 403 | 403 | ✓ |

后续阶段接入的新页面沿用同一矩阵规则：学生端、维修端、管理端路由分别声明 `meta.role`，值为对应角色数值。

## 5. 路由守卫规则

按以下顺序执行，命中即返回：

1. 未登录访问非 `public` 页面：跳转 `/login`，并通过 `redirect` 查询参数保留原地址。
2. 已登录访问 `/login`：跳转当前角色的默认首页。
3. 已登录访问带 `meta.role` 且角色不符的页面：跳转 `/403`。
4. 其余情况放行。

前端权限控制只用于改善交互体验；所有权限判断最终由后端执行，页面级 403 不豁免任何接口的鉴权校验。

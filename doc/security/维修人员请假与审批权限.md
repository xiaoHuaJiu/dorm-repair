# 维修人员请假与审批权限

> **状态：开发完成，暂未测试。** 项目当前无法启动，本文描述的权限规则未经过运行时验证。

本文描述 PLAN-9（维修人员请假）的接口访问控制与数据权限。通用登录与路由权限见《前端登录与路由权限.md》。

## 1. 接口级权限

| 接口 | 角色 | 实现方式 |
|---|---|---|
| `POST /api/worker/leave-requests` | 维修人员 | 类级 `@PreAuthorize("hasRole('WORKER')")` |
| `GET /api/worker/leave-requests` | 维修人员 | 同上 |
| `GET /api/worker/leave-requests/{id}` | 维修人员 | 同上 |
| `GET /api/admin/leave-requests` | 管理员 | 类级 `@PreAuthorize("hasRole('ADMIN')")` |
| `GET /api/admin/leave-requests/{id}` | 管理员 | 同上 |
| `POST /api/admin/leave-requests/{id}/review` | 管理员 | 同上 |

角色不符返回 HTTP 403 / 10003；匿名访问返回 HTTP 401 / 10002。

## 2. 数据权限

- **维修人员端强制本人范围**：`workerId` 由后端通过登录上下文解析（`CurrentWorkerResolver`），前端提交的 `workerId` 一律被忽略；查询接口不接受该参数。
- **行级校验**：维修人员详情接口按 `leaveId + workerId` 联合查询，非本人请假返回 HTTP 404 / 10004（不区分「不存在」与「无权限」，避免泄露他人在职请假信息）。
- **管理员可查全量**：管理员列表支持按人员、状态、时间筛选；详情可查看任意请假。
- 当前账号没有维修人员档案时（如停用账号），提交与查询均返回 HTTP 404 / 15002。

## 3. 提交与审批的幂等防重

- 提交与审批各自要求 `bizNo`，前端不得自动更换 `bizNo` 规避重复。
- Redis 门闩（10 分钟 TTL）拦截并发重复；`sys_idempotent_record` 唯一约束兜底。
- 相同 `bizNo` 不同内容返回 HTTP 409 / 17004，防止请求篡改后借旧 `bizNo` 重放。
- 审批仅允许「待审批」状态（数据库 CAS 条件更新），重复审批、并发审批只有一次成功，其余返回 HTTP 409 / 10005。

## 4. 定时任务的系统身份

请假生效与结束任务以 `SYSTEM` 身份写操作日志（`username=SYSTEM`、`roleType=4`、`requestMethod=SCHEDULED`），不占用任何用户令牌，也不经过 HTTP 接口，前端无法触发。管理员提醒（汇总告警）直接写 `repair_dispatch_alert`，供管理员异常工单页消费。

## 5. 越权防护清单

| 风险 | 防护 |
|---|---|
| 维修人员查看他人请假 | 查询强制 `worker_id = 当前维修人员`；详情联合条件查询 |
| 维修人员指定 `workerId` 替他人请假 | 后端忽略客户端人员参数，从登录上下文解析 |
| 管理员重复/并发审批 | bizNo 幂等 + 审批状态 CAS 条件更新 |
| 驳回后仍生效 | 生效任务只扫描 `status=1` 的请假 |
| 请假期间被派新单 | 生效任务置 `work_status=请假中` + 派单候选 SQL 过滤请假人员 |
| 篡改 `bizNo` 重放旧请求 | 请求摘要（内容哈希）比对，不符返回 HTTP 409 / 17004 |

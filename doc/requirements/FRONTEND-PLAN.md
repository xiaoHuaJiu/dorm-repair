- 学校全部工单查询。
- 聚合工单详情。
- 完整生命周期轨迹。
- 学生取消工单。
- 重复报修检测。
- 创建报修及幂等提交。
- 工单操作权限或可用操作字段。

## P3：维修流程阻塞

- 接单。
- 维修过程记录。
- 材料登记。
- 中断和恢复。
- 转派申请。
- 完成维修。
- 学生确认、评价和返工。

## P4：管理流程阻塞

- 工作台统计。
- 异常工单。
- 转派审批。
- 匹配维修人员查询。
- 人工派单。
- 请假申请和审批。

## P5：消息阻塞

- 消息列表。
- 未读数量。
- 标记已读。
- 消息业务类型及目标资源编号。

# 五、建议实施批次

建议按可独立验收的小批次推进：

1. 工程基础、主题、路由和登录注册。
2. 公共布局、公共组件和状态体系。
3. 四项基础配置管理。
4. 工单公共列表、详情和生命周期。
5. 学生完整报修路径。
6. 维修人员完整处理路径。
7. 管理员审批和派单路径。
8. 消息中心。
9. 全路径联调、视觉还原和测试。

每个任务完成时都应同时满足：

- 页面可以独立打开。
- 使用真实 API 模块。
- 没有演示业务数据。
- 具备加载、空数据和错误状态。
- 关键交互可验证。
- 相关验证记录已更新。

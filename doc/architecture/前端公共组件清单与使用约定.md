# 前端公共组件清单与使用约定

本文对应 `FRONTEND-PLAN.md` 阶段 F3(公共组件),记录公共组件的清单、使用约定与状态交互规范。所有组件位于 `frontend/src/components/common/`,布局壳位于 `frontend/src/layouts/`。组件只承载视觉与交互,不内置演示数据,数据一律由页面层通过 API 提供。

## 1. 组件清单

| 组件 | 文件 | 职责 | 主要使用页面 |
|---|---|---|---|
| `MobileAppShell` | `layouts/MobileAppShell.vue` | 学生端/维修端移动布局:顶栏、页头、内容、底部导航 | 全部学生端、维修端页面 |
| `AdminAppShell` | `layouts/AdminAppShell.vue` | 管理端布局:顶栏、分组侧栏、页头、内容 | 全部管理员端页面 |
| `OrderStatusTag` | `components/common/OrderStatusTag.vue` | 工单状态标签,统一文案与色调 | 三端列表、详情、工作台 |
| `OrderCard` | `components/common/OrderCard.vue` | 移动端工单卡片,整卡可点击 | 学生端/维修端列表与工作台 |
| `OrderTableRow` | `components/common/OrderTableRow.vue` | 管理端工单表格行,整行可点击 | 管理员工单、异常、派单列表 |
| `OrderTimeline` | `components/common/OrderTimeline.vue` | 工单生命周期轨迹,最新在前 | 三端工单详情 |
| `PageState` | `components/common/PageState.vue` | 加载/错误/空数据/内容四态容器 | 所有远程数据页面 |
| `FilterBar` | `components/common/FilterBar.vue` | 胶囊筛选按钮组 | 三端工单列表、管理员列表 |
| `ConfirmDialog` | `components/common/ConfirmDialog.vue` | 危险操作确认弹窗 | 取消、删除、启停、审批、派单 |
| `FormDialog` | `components/common/FormDialog.vue` | 新增/编辑表单弹窗 | 基础配置、报修、请假等表单 |
| `ImageUploader` | `components/common/ImageUploader.vue` | 图片缩略图预览、选择与移除 | 报修、维修记录、完成维修 |
| `PaginationBar` | `components/common/PaginationBar.vue` | 分页条：共 N 条、上一页/下一页、第 x/y 页 | F4 基础配置页（故障类型、工作时间、维修人员） |
| `RegionTreeNode` | `components/admin/RegionTreeNode.vue` | 四级区域树递归节点：折叠分支/叶子行、增删按钮 | 区域配置页 |
| `WorkerCard` | `components/admin/WorkerCard.vue` | 维修人员卡片：状态、技能、区域、负载与操作按钮 | 维修人员管理页 |

公共常量与类型:

- `constants/order.ts`:工单状态(0—7)、状态文案与色调、流转操作类型(1—6),数值与后端枚举一致。
- `constants/role.ts`:角色数值(1学生/2维修/3管理员)、角色文案、角色首页路径。
- `types/order.ts`:`OrderListItem`、`OrderFlowItem`,字段与后端 VO 对齐。

## 2. 组件使用约定

### 2.1 布局壳

- 学生端与维修端页面必须使用 `MobileAppShell`,传入 `role`(1/2)、`title`、`navItems`;页面内容放默认插槽。
- 管理员端页面必须使用 `AdminAppShell`,传入 `title`;页面内容放默认插槽。
- 两壳的导航条目都按“路由已注册才显示”过滤:新增页面路由后导航自动出现,无需改壳代码。
- 页头右侧操作(如“我要报修”)使用 `head-action` 插槽;维修端消息入口使用 `before-actions` 插槽。

### 2.2 工单卡片与表格行

- 卡片/行整体可点击进入详情,`OrderCard`/`OrderTableRow` 分别监听 `open` 事件;页面层负责跳转,组件不持有路由逻辑。
- 不渲染多余的“查看详情”按钮;操作按钮(取消、接单等)通过 `actions` 插槽承载,组件内部自动排除 `button/a/input/select/textarea/label` 的点击冒泡。
- 键盘可达:`OrderCard`/`OrderTableRow` 均支持 Enter 与空格触发打开,具备 `role="link"`、`tabindex="0"` 和 `aria-label`。

### 2.3 状态标签

- 页面必须透传后端 `statusName`;后端未返回时组件按状态数值映射默认文案,不允许页面自行写死状态文本。
- 状态数值与文案映射只维护在 `constants/order.ts`,页面不得重复定义。

### 2.4 生命周期轨迹

- `flows` 按接口返回顺序传入,组件内部倒序展示(最新在前),与原型一致。
- 后端 `flows` 目前无操作人姓名,组件不伪造姓名;页面层通过 `operatorNameOf`/`assigneeNameOf` 回调提供姓名映射,后端补充字段后移除回调。
- 转派节点仅在 `originalAssigneeId` 与 `newAssigneeId` 均存在且不同时展示“负责人:甲 → 乙”。

### 2.5 弹窗

- 危险操作使用 `ConfirmDialog` 并设置 `danger`;提交中传入 `loading`,组件禁用按钮并阻止 Esc 关闭。
- 表单使用 `FormDialog`,校验失败或接口错误文案通过 `error` 属性传入;Esc 可关闭,提交中不可关闭。

### 2.6 图片上传

- `ImageUploader` 只负责选择、预览与移除；上传动作由页面层调用上传接口，成功后把地址追加到 `modelValue`。
- 文件上传接口缺失期间，页面层传入 `disabled` 并通过 `hint` 插槽提示“暂不支持上传”，禁止生成假 URL。

### 2.7 F4 基础配置组件

- `PaginationBar` 只展示总数、页码与翻页，页面层负责切换页码后重新请求；后端 `pageNum` 从 1 开始。
- `RegionTreeNode` 递归渲染，房间为叶子行，其余层级为 `<details>` 折叠分支；增删按钮受 `editing` 控制（原型用 `hidden` 属性切换，与 CSS `[hidden]` 规则配套）；无子节点时删除按钮禁用并 title 提示，有子节点点击由页面层提示“请先删除下级节点”。
- `WorkerCard` 在挂载时自行加载技能与负责区域（失败回退“—”），页面层负责列表、编辑、启停确认与技能/区域配置弹窗；负载行在 F5 工单查询就绪前显示“—”。

## 3. 状态与交互规范

### 3.1 远程数据页面四态

所有通过接口取数的页面必须使用 `PageState` 承载:

| 状态 | 呈现 | 行为 |
|---|---|---|
| 首次加载 | 骨架屏(`aria-busy`) | 接口返回后切换 |
| 加载失败 | 错误文案 + 重试按钮(`role="alert"`) | 点击重试重新请求 |
| 空数据 | 空标记 + 文案(如“暂无工单”) | 不填充演示数据 |
| 正常 | 页面插槽内容 | 按角色渲染 |

### 3.2 提交操作

- 所有提交按钮在请求进行中进入禁用并展示“提交中…/处理中…”等文案,防止重复提交。
- 业务失败提示优先使用后端 `message`;网络错误提示“网络异常,请稍后重试”。
- 幂等与并发要求以后端接口文档为准;前端只做按钮级防重,不依赖前端防重作为业务正确性保障。

### 3.3 键盘与可访问性

- 可点击卡片/行支持 Enter/空格,聚焦样式使用全局 `:focus-visible`。
- 弹窗具备 `role="dialog"`、`aria-modal="true"` 与标题关联;Esc 关闭。
- 筛选按钮组使用 `aria-pressed` 表达选中态;表单控件使用可见 label。

### 3.4 三端差异

- 学生端/维修端使用卡片列表 + 胶囊筛选;管理端使用表格行 + 表单筛选,视觉均以原型为准。
- 三端详情复用 `OrderTimeline`,但数据接口、可见字段与操作按钮按角色独立实现(F5/F6/F7/F8 接入)。

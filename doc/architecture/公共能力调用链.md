# 公共能力调用链

正常请求链路为：JWT 认证过滤器校验 `Authorization: Bearer <token>`，并按令牌中的用户编号重新查询 `sys_user`、确认账号仍处于可用状态，随后把 `LoginUser` 写入 Spring Security 上下文。Controller 接收并校验 DTO，Service 通过 `UserContext` 获取当前操作人，Mapper 执行数据访问；分页查询在 Mapper 调用前紧邻执行 `PageHelper.startPage`，查询结果转换为项目自有 `PageResult`，再由 Controller 包装为 `Result`。

```text
HTTP → JWT 过滤器 → SecurityContext → Controller → DTO 校验
                                      ↓
                         Service → UserContext → Mapper
                         Mapper 查询 → PageResult → VO → Result → HTTP
```

异常沿调用链反向传播，由 `GlobalExceptionHandler` 转换为匹配的 HTTP 状态和统一 `Result`。认证过滤器阶段产生的 401/403 无法进入控制器，因此由 Security 专用处理器输出相同结构。

PageHelper 仅是数据访问实现细节。Controller、前端协议和业务 VO 不得引用 `PageInfo` 等 PageHelper 类型。越界页返回空集合，不自动跳转到最后一页。

## 登录与角色权限

登录接口根据用户名查询 `sys_user`，使用 BCrypt 校验密码，并校验账号状态和逻辑删除标记。登录成功后签发有限有效期的 JWT；令牌密钥和有效期只通过环境变量注入。受保护接口使用 `@PreAuthorize` 声明角色要求，管理员、维修人员和学生的角色互不继承。

## 数据范围边界

阶段 1 不采用自动改写 SQL 的 DataScope AOP。后续业务接口必须分三层落实数据边界：

1. Controller 使用 `@PreAuthorize` 判断当前角色能否调用接口。
2. Service 从 `UserContext` 获取当前用户身份，并把本人或本人负责的范围作为显式 Mapper 查询条件；不得信任前端传入的 `studentUid`、`workerId`、`operatorId` 等身份字段。
3. Service 对详情、修改和操作类请求再次检查资源归属及业务状态，越权统一返回 HTTP 403。

管理员默认访问全部业务数据；维修人员只访问本人相关或当前由本人负责的数据；学生只访问本人提交或拥有的数据。具体表的过滤字段随对应业务模块在后续阶段落地。

# 返工生命周期与工单告警设计

学生在待确认状态可确认完成或在原工单申请返工。返工不创建新工单、不更换负责人；主表原子增加 `rework_count` 并进入返工中，同时创建未完成的 `repair_rework_record`。维修人员再次提交结果时，当前返工记录和工单状态在同一事务中更新。

第一次返工不告警；第二次写 `REWORK_WARNING`（等级 2）；第三次及以后每轮写 `REWORK_EXCEPTION`（等级 3）并设置异常标志。`repair_order_alert` 通过 `(order_id,rework_no,alert_type)` 去重，并与派单失败专用表分离。

状态、返工记录、告警、流转和操作日志属于同一事务，任何核心写入失败均回滚。

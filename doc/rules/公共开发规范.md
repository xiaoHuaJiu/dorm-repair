# 公共开发规范

1. Controller 负责请求接收、参数校验和响应包装；业务规则进入 Service；数据访问进入 Mapper。
2. 成功统一使用 `Result.success`，可预期业务失败抛出 `BusinessException`，不得自行拼装不一致的错误 JSON。
3. 未知异常必须记录完整 Throwable，但客户端只能收到通用系统错误消息。
4. 分页参数统一使用 `PageQuery`；`PageHelper.startPage` 必须紧邻目标 Mapper 查询，避免分页上下文污染后续 SQL。
5. Mapper 查询结果立即转换为 `PageResult`；不得在接口协议中暴露 `PageInfo`。
6. 操作人身份统一由 `UserContext` 获取，DTO 不接收操作人编号。
7. 前端业务请求统一调用 `request<T>`，不得重复实现响应拆包、401 清理和错误提示。
8. 新增公共工具前先确认现有公共能力无法满足，避免同义类和重复错误码。
